A narrative of how this plugin was built, for anyone reading the repo later. It was built
by running its own review-and-triage workflow on itself (the plugin is the dogfood of its
own design). Personal data about the maintainer is intentionally omitted — this is a public

## How it was built — the plan, executed

The spec (`docs/specs/2026-07-20-…`) and plan (`docs/plans/2026-07-20-…-plan.md`) were
already written and reviewed. This session **executed the 7-task plan**, then added an 8th
task from review feedback.

Execution used the `executing-plans` discipline (load plan → review critically → execute
task-by-task → verify → commit each). Direct execution was chosen over dispatching subagents
because the deliverables are six small files whose content was mostly specified in the plan,
and the three `SKILL.md` bodies needed the full spec/review context held by one author.

Each task was verified structurally (there is no test framework — the plugin is Markdown +
JSON + a shell hook) and committed as its own green checkpoint:

1. Plugin + marketplace scaffold
2. Thin SessionStart hook
3. Shared review-loop shape
4. `triage` skill
5. `doc-review-loop` skill
6. `code-review-loop` skill
7. Public-repo hygiene (README, `.gitignore`)
8. `triage` skill v2 — faithful port of the full asking discipline (added after review)

## Key decisions made during the build

- **Composition contracts were verified against the *real* installed skills**, not assumed.
  Before writing each loop skill, the actual `ce-doc-review` / `ce-code-review` /
  `receiving-code-review` / `subagent-driven-development` skills were read to confirm: that
  `mode:headless` and `mode:agent` exist; that the doc-review exit envelope is documented in
  `synthesis-and-presentation.md` (not `walkthrough.md`); that the code-review JSON really
  carries `verdict` and `actionable_findings`; and that a `## Model Selection` section exists
  to configure rather than rebuild. Every claim in the plan checked out.
- **The hook stays Unix-only in v1** (a direct script call). superpowers ships a
  cross-platform `run-hook.cmd` wrapper; adopting it was deferred to v1.1 with its reason
  recorded in `TODO.md` (Simplicity-First for a macOS prove-the-core release).
- **`/plugin install` verification is a human step.** Those are interactive REPL commands,
  not shell — the build verified manifest *structure* here and left the actual install/load
  check to a terminal.

## The triage-skill refinement (the substantive part)

The first `triage` skill was a condensed summary. Review feedback pushed it to a **faithful,
generic port of the full asking discipline**: the bundling anti-pattern, the inert follow-up
catcher, comparing competing alternatives (prose pros/cons + an at-a-glance table + a
weighted decision matrix), the full no-ghost-references pattern, send-the-picker-in-the-same
-turn, tagging, glyph rules, acronym expansion, and the "Other" side-channel.

The sharpest correction was **the Skip vocabulary**. The options a person picks are
`Apply / Defer / Drop`: Apply = do it now; Defer = not now, the item stays open, come back
later; Drop = the only explicit discard. The Skip button means Defer — never a silent drop,
never "you choose." An unanswered question is simply pending until answered. `commit before
review` was added to the shared loop (review runs on a committed, green artifact).
